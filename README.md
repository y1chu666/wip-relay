# WIP Relay

自托管的中继服务端。多台设备交替使用同一个 Git 仓库时，它把各设备工作区的状态转达给其他设备，让使用者在下笔之前知道对端仍有未提交的改动。它不上传文件内容，也不持有内容密钥。

[English](README.en.md)

> [!NOTE]
> 本项目由 AI 实现，人类提供思路、需求与判断。范围界定、取舍与验收标准由人类决定；代码、文档与测试由 AI 撰写。

## 它做什么

- 接收并保存各设备签名的状态记录，供同一频道的其他设备读取。
- 维护频道与设备列表，处理注册、吊销与退役。
- 校验请求签名与时间窗口，拒绝重放。
- 对请求头、请求体、回应与空闲连接设有时限，慢速连接无法长期占用资源。

它不认识 Git，也不接触任何文件内容：记录里只有设备、序号与密文，连文件路径都是加密的。

## 它不做什么

- 不同步内容，不解决冲突，不做跨中继复制，也没有账号体系。
- 不主动推送通知，所有读取都由客户端发起。

## 快速开始

要求 Go 1.27 或更高版本，也可以直接取用发布页的二进制。

```bash
wip-relay init --config wip-relay.toml
wip-relay serve --config wip-relay.toml
```

`init` 写入配置样例，并生成一枚注册凭证。凭证只显示一次，服务端只保存它的摘要。设备注册完毕后，把配置中的 `[registration] enabled` 改为 `false`，再执行 `wip-relay reload` 使其生效。

发布产物为单一静态二进制，不依赖外部运行库。默认只允许公签 HTTPS 与钉住自签证书两种传输方式；明文与忽略证书错误都必须显式配置，程序不会自动降级。

## 部署建议

- 置于反向代理之后，或直接启用 HTTPS。
- 只暴露必要端口；数据目录设最小权限，并定期备份。
- 以非特权用户运行。
- 置于反向代理之后时，来源地址维度看到的是代理的地址，按真实来源限流应在代理侧完成。服务端不解析、也不信任转发头。

## 搭配使用

WIP Relay 可与 [Vault WIP](https://github.com/y1chu666/vault-wip) 插件搭配：插件采集工作区状态，经中继转达给同一频道的其他设备。

中继本身不限定于 Obsidian。协议公开，见[协议说明](docs/protocol.md)；任何按协议实现的客户端都可以接入，包括与笔记无关的仓库。

## 版本与兼容

本仓库 `0.2.0` 起记录格式为 v2，与 `0.1.0` 的 v1 不兼容。中继不解析记录内容，但参与记录签名校验，因此客户端升级记录格式时，中继必须同步升级；两端版本应成对使用。
