# 测试说明

## 原则

- 测试固定行为，不固定实现。只改实现而不改行为时，测试不应失败。
- 安全相关的行为必须有反向测试：该拒绝的请求确实被拒绝。
- 测试用密钥在运行时生成，不写入仓库。
- 测试中出现的主机名、端口、设备名一律使用保留域名与示例值。

## 分层

1. **单元测试**：配置解析与校验、签名与鉴别、重放判定、序号比较、限流与上限、存储读写。
2. **集成测试**：以真实进程启动服务，走完整请求链路，覆盖注册、上报、拉取、吊销、退役，以及降级状态下的拒绝行为。
3. **端到端测试**：由客户端仓库维护。若本机同时保有两边源码，客户端用例会编译并启动本服务端，验证跨语言签名与加密载荷是否对得上；这部分不纳入本仓库的持续集成。
4. **渗透测试**：面向 Web 接口与二进制本身，由独立于实现过程的第三方执行；只记录结论，不保留产物。

## 测试数据

- 主机名使用 `relay.example.com`、`relay.invalid` 一类保留域名。
- 设备名使用 `device-a`、`device-b`。
- 频道名使用 `repo-example`。
- 一切密钥、凭证与令牌均在测试运行时生成。

## 持续集成

- 每次提交与合并请求运行格式检查、静态检查、竞态检测与全部测试。
- 须通过 `gofmt` 与 `go vet`；测试以 `-race` 运行。
- 覆盖率门禁为百分之九十，低于门禁即判失败。
- 交叉编译覆盖 `linux/amd64`、`linux/arm64`、`windows/amd64`、`windows/arm64`，任一平台编译失败即判失败。
- 发布产物由流水线构建，产物不进入版本库。

## 不进入持续集成

- 渗透测试。
- 需要外网、真实主机或真实证书的用例。
- 性能与压力测试，按需手工执行。
